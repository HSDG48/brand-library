# Brand Library

Our public archive of complete brand kits for the brands we manage. Each brand gets
the full set of files a design studio would hand over: logos, variations, wordmarks,
icons, favicons, colours, type, a brand guide and a business profile.

## Goals

1. **One permanent home** for every brand's assets, versioned so nothing is ever lost.
2. **Studio-quality kits**: every brand gets the same complete set (see the list below).
3. **Public and easy to grab**: anyone (us, the client, a printer, a journalist) can download
   the right file in the right format without asking.

## Where it lives

| Place | Role |
|---|---|
| **GitHub (public repo)** | Main home. Version history, permanent links, free. |
| **GitHub Pages** | A website built from the repo: one page per brand with preview + download buttons. |
| **Google Drive (optional mirror)** | For people who don't use GitHub. A zip per brand, synced from the repo. |

GitHub is the main copy because it keeps every version and its links don't break.
Drive is just a convenience copy.

## Public vs private (team only)

| Public repo `brand-library` | Private repo `brand-library-team` |
|---|---|
| Logos, lockups, icons, favicons, social images | Business cards with real people's names, roles, direct phones |
| Brand guide, business profile (public contacts only) | Letterhead, envelopes, invoices filled in with company data |
| **Blank** stationery templates (sample name "Nombre Apellido") | Editable source files (.fig, print-ready PDFs with bleed for the printer) |
| | Anything the client hasn't OK'd for public use yet |

Rule of thumb: if it carries a real person's details or is only useful to our team, it goes private.

**How it works:** this folder is the private repo (`brand-library-team`) and holds everything.
The public repo is a filtered copy: [`private.txt`](private.txt) lists what stays team-only
(each brand's `private/` folder, `source/`, `.fig` files, print PDFs with bleed). Refresh the public copy with:

```
node scripts/export-public.mjs            # writes ../brand-library-public, keeps its .git
```

Then commit and push from `../brand-library-public`. Never edit the public copy by hand: it is overwritten on every export.

## Design tools: code master, Figma for stationery

- **Logo system, icons, social, guide, profile**: generated by scripts from `brand.json` + master SVGs.
  Exact, rebuildable, every size in one command. Figma gets a **mirror** of these (a public
  view-only file per brand) for people who prefer browsing there.
- **Stationery (business cards, letterhead, envelope, signature layout)**: designed in **Figma**,
  because it's hand-layout work the team edits per person. The designer shares the Figma link or `.fig`,
  we export the assets, file them under `stationery/` (blank template → public, filled-in → private repo).

## Rules before a brand goes public

- **Client permission.** These are the clients' trademarks. Get a written OK (an email is enough)
  before publishing a brand. Record it in that brand's `brand.json` (`publishPermission`).
- **Licence.** Our guide text and layouts: CC BY 4.0. **Logos and brand names stay the
  trademark of their owners.** People may use them to refer to the brand (press, directories,
  partner pages), not to pretend to be it. This line goes in every brand's README.
- **No private data.** Business profiles only carry public info (public email, phone, address,
  socials). No personal numbers, no tax IDs unless already public.

## What every brand kit contains

**Logo system** (master files are SVG; everything else is exported from them)
- Primary logo (full colour)
- Horizontal / landscape lockup
- Stacked / vertical lockup
- Wordmark only (the name set in type)
- Logomark / symbol only (the icon without the name)
- Each of the above in: full colour, one colour (black), reversed (white), on brand colour
- Clear space and minimum size rules

**Icons and app assets**
- Favicons: `favicon.ico` (16/32/48), `favicon.svg`, `apple-touch-icon.png` (180),
  `icon-192.png`, `icon-512.png`, `site.webmanifest`
- Social avatars: square 1024 + round-safe version
- Social covers / OG image (1200×630), plus banner sizes for LinkedIn, X, Facebook, YouTube

**Brand foundations**
- Colour palette: HEX, RGB, CMYK, Pantone (nearest), with usage ratios and contrast checks
- Typography: primary + secondary fonts (free/Google Fonts where possible), type scale
- Tone of voice: 3–5 words, do / don't examples
- Logo misuse page (what not to do)

**Documents**
- Brand guide: web page (on the Pages site) + PDF. **Portrait pages only (A4 vertical, 210 × 297 mm)**,
  never landscape slides. Existing landscape guides (e.g. from Figma) get re-laid out in portrait.
- Business profile: one-page PDF + text (about, boilerplate, services, contacts, socials)
- Email signature (HTML)

**Formats delivered**: SVG, PDF (vector, print), PNG (transparent, 512 / 1024 / 2048 / 4096 px), JPG for covers.

## How we do each brand (one per session)

1. **Intake.** First decide **which languages** the brand's documents are made in (guide, profile,
   signature, social text). Then answer the questionnaire in `templates/intake-questionnaire.md` and share the logo files.
2. **Review the logo.** If it's only a JPG/PNG, rebuild it as a clean vector SVG first.
3. **Build the logo system.** Lockups, wordmark, mark, colour versions. You approve.
4. **Foundations.** Colours, fonts, tone. You approve.
5. **Export.** A script turns the master SVGs + `brand.json` into every size and format,
   so all brands come out consistent.
6. **Guide + profile.** Built from `brand.json`, so they always match the files.
7. **QA.** Check every file opens, is sharp, and the guide links work.
8. **Publish.** Mark it done in `BRANDS.md`, commit, push, update the Pages site and Drive zip.
